## 2. Decisiones

### Datos (`src/data/aminoacids.ts`)
- **Fuente única de valores numéricos**: *Lehninger Principles of Biochemistry*, 8.ª ed. (Nelson & Cox, 2021), **Tabla 3-1**. De ahí salen: Mr, pK1 (α-COOH), pK2 (α-NH3+), pKR, pI e índice de hidropatía (que en esa tabla es la escala de Kyte-Doolittle, 1982). Anotar la fuente en un comentario al inicio del archivo. Si algún valor no lo tienes con certeza, márcalo `// TODO verificar` y lístalo en el "Resultado"; José Manuel lo cotejará con el libro.
- **Masa**: `molecularWeight` = Mr del aminoácido libre según Lehninger (enteros, g/mol). No se agrega masa monoisotópica en esta fase.
- **Esencialidad**: tres estados, no booleano: `'essential' | 'conditional' | 'nonessential'` (clasificación de Lehninger para humanos adultos: 9 esenciales; condicionalmente esenciales Arg, Cys, Gln, Gly, Pro, Tyr). Esto **sustituye** el booleano mencionado en el plan maestro.
- **Codones**: en ARN (A, C, G, U), código genético estándar.
- **SMILES**: isomérico, forma **neutra** (–NH2 / –COOH, sin cargas formales), estereoquímica L (Cys queda como R por CIP; Ile y Thr con su segundo centro quiral). Sin hidrógenos explícitos salvo los que exija la estereoquímica. His en el tautómero **Nε2–H** (el mismo que tendrá el 3D, ver abajo).
- **Nombres**: `name` en español con la forma de Lehninger en español (p. ej. "Ácido aspártico"), más `aliases` para búsqueda ("aspartato"). El inglés no es necesario.
- **Grupos ionizables con nombres de átomo**: para colorear carga y calcular la nube, cada aminoácido declara sus grupos ionizables con los nombres de átomo del CCD. Esto es dato bioquímico, así que vive en `aminoacids.ts`, no en el visor.

Forma propuesta (ajústala si hace falta, pero sin quitar campos):

```ts
export type LehningerGroup = 'nonpolar' | 'aromatic' | 'polar' | 'positive' | 'negative'
export type Essentiality = 'essential' | 'conditional' | 'nonessential'

export interface IonizableGroup {
  kind: 'alpha-carboxyl' | 'alpha-amino' | 'side-chain'
  pKa: number
  /** 'acid': neutro protonado, −1 desprotonado. 'base': +1 protonado, neutro desprotonado. */
  type: 'acid' | 'base'
  /** Átomos pesados (nombres CCD) sobre los que se reparte la carga, p. ej. ['OD1', 'OD2']. */
  atoms: string[]
}

export interface AminoAcid {
  code3: string            // 'Ala' (mostrar); el código CCD es code3.toUpperCase()
  code1: string            // 'A'
  name: string             // 'Alanina'
  aliases: string[]
  group: LehningerGroup
  smiles: string           // neutro, isomérico
  molecularWeight: number  // Mr, Lehninger
  pKa: { carboxyl: number; amino: number; sideChain?: number }
  pI: number
  hydropathy: number       // Kyte-Doolittle
  essentiality: Essentiality
  codons: string[]         // ARN
  standard: boolean        // true para los 20
  note: string             // una frase característica, texto original
  ionizableGroups: IonizableGroup[]
}

export const AMINO_ACIDS: AminoAcid[]
export const GROUPS: Record<LehningerGroup, { label: string; cssVar: string }>
```

- **Cys y Tyr** llevan su pKR en `ionizableGroups` (tipo `'acid'`), aunque a pH 7 casi no aporten carga.
- **Grupos de Lehninger** exactamente como en el plan maestro (Gly, Ala, Pro, Val, Leu, Ile, Met no polares alifáticos; Phe, Tyr, Trp aromáticos; Ser, Thr, Cys, Asn, Gln polares sin carga; Lys, Arg, His positivos; Asp, Glu negativos).

### Química pura (`src/chem/`)
Funciones sin datos propios, reutilizables en la Fase 2:
- `groupCharge(group, pH)` y `netCharge(aa, pH)` por Henderson-Hasselbalch (cargas fraccionarias).
- `computePI(aa)`: pH en que `netCharge` = 0, por bisección en [0, 14]. Se usa **solo en pruebas** para validar el pI tabulado; la interfaz muestra el pI de Lehninger.

### Regla de neutralidad (2D y 3D)
**Todos los aminoácidos se muestran neutros** (–NH2 / –COOH, cadenas laterales sin carga), en 2D y en 3D, en todas las pestañas. Las formas cargadas (zwitterión, cadenas laterales ionizadas) **solo** aparecen donde se enseña la protonación: el simulador de pH de la Fase 2. En la Fase 1 no se dibuja ninguna estructura cargada.

El color "carga a pH 7" y la nube de carga **no cambian la estructura**: son capas que se pintan sobre la molécula neutra para indicar qué carga tendría a pH 7. Su leyenda lo dice explícitamente: "La estructura se dibuja neutra; los colores indican la carga que tendría a pH 7".

### Estructuras 3D (`public/structures/`)
- Se generan con un script `scripts/fetch-structures.mjs` que se ejecuta una vez y cuyos resultados **se commitean**. La app nunca descarga nada en tiempo de ejecución.
- El script descarga de RCSB, por cada código CCD, el SDF ideal (`https://files.rcsb.org/ligands/view/{CCD}_ideal.sdf`) y el CIF del componente (`https://files.rcsb.org/ligands/view/{CCD}.cif`).
- **Nombres de átomo**: el SDF **no trae nombres** (ya verificado), solo elementos. El script toma los nombres del CIF (`_chem_comp_atom.atom_id`), comprueba que el orden de elementos coincide átomo por átomo con el SDF y escribe `public/structures/atom-names.json` (`{ "ALA": ["N", "CA", ...] }`, en el orden del SDF ya neutralizado). `MolViewer` asigna esos nombres a los átomos al cargar.
- **Neutralización (ya verificado)**: los SDF ideales del CCD traen **Lys, Arg e His con la cadena lateral protonada** (carga formal +1, línea `M  CHG`); Asp, Glu y el resto ya vienen neutros. El script los neutraliza quitando un hidrógeno del nitrógeno cargado, su enlace y la línea `M  CHG`, y renumerando:
  - **Lys**: quitar `HZ3` de `NZ` → –NH2.
  - **Arg**: quitar `HH22` de `NH2` (que tiene doble enlace con `CZ`) → =NH; queda la guanidina neutra.
  - **His**: quitar `HD1` de `ND1` (que tiene doble enlace con `CE1`) → tautómero neutro Nε2–H.
  - Los átomos se identifican por nombre (vía el CIF), no por índice. Si la estructura del archivo no coincide con lo descrito, el script falla con un mensaje claro en vez de adivinar.
- Archivos resultantes: `public/structures/{CCD}.sdf` (p. ej. `ALA.sdf`) + `atom-names.json`. El Resultado debe decir qué tres archivos se modificaron respecto al original del CCD.
- Ni el color "carga a pH 7" ni la nube usan cargas formales del SDF (ya no hay): usan `ionizableGroups` + Henderson-Hasselbalch a pH 7.

### MolViewer nivel básico (`src/components/MolViewer/`)
- **Carga diferida**: 3Dmol se importa dinámicamente (`import('3dmol')`) dentro del componente, para no inflar el bundle inicial. La pestaña muestra un esqueleto/spinner mientras carga.
- **API declarativa**, controlada por props, para que fases posteriores (quiz, recorridos) la manejen desde fuera:

```ts
interface MolViewerProps {
  molecule: { kind: 'sdf'; url: string; aminoAcid?: AminoAcid } // 'pdb' llega en la Fase 4
  representation?: 'sticks' | 'ballstick' | 'spheres' | 'lines'
  colorMode?: 'element' | 'group' | 'hydrophobic' | 'kyte-doolittle' | 'polarity' | 'charge'
  surface?: 'none' | 'charge-cloud' | 'hydrophobicity'
  surfaceOpacity?: number
  showHydrogens?: boolean
  labels?: 'none' | 'atoms'
  spoilerFree?: boolean       // regla anti-spoiler
  toolbar?: boolean           // barra de herramientas propia del kit
  onStateChange?: (s: MolViewerState) => void
}
```

  Puede funcionar no controlado (estado interno) si no se pasan props; la barra de herramientas edita ese estado.
- **Representaciones**: sticks, ball & stick, esferas (vdW), líneas. Cartoon y superficie molecular "pura" quedan para la Fase 4 (no tienen sentido en un aminoácido suelto, salvo como soporte de las dos superficies de abajo).
- **Modos de color para aminoácido suelto**. Regla común: en los modos de propiedad, el **esqueleto** (N, CA, C, O, OXT y sus H) va en gris neutro y solo se colorea la **cadena lateral**; así se ve qué aporta cada una.
  - `element`: CPK.
  - `group`: cadena lateral con el color de su grupo (`--group-*`; leer las variables CSS o duplicarlas en un único módulo de paleta, no en varios sitios).
  - `hydrophobic`: binario, hidropatía > 0 → hidrofóbico (naranja), ≤ 0 → hidrofílico (azul verdoso).
  - `kyte-doolittle`: gradiente continuo de −4.5 a +4.5 con leyenda.
  - `polarity`: no polar / polar / cargado + / cargado −, según el grupo de Lehninger (aromáticos cuentan como no polares en esta vista; Tyr se explica en su "¿qué estoy viendo?").
  - `charge`: átomos de `ionizableGroups` coloreados por su carga fraccionaria a pH 7 (rojo −, azul +, intensidad proporcional); el resto blanco/gris.
- **Nube de carga (pH 7)**:
  - Cargas: cada grupo ionizable aporta su carga de Henderson-Hasselbalch a pH 7, repartida a partes iguales entre sus `atoms`.
  - Potencial: Coulomb con dieléctrico dependiente de la distancia, ε(r) = 4r, es decir φ(p) = Σ qᵢ / (4 rᵢ²) en unidades arbitrarias; r mínimo de 1 Å para evitar singularidades.
  - Se calcula en un **Web Worker** (`chargeCloud.worker.ts`, con `new Worker(new URL(..., import.meta.url), { type: 'module' })`) sobre una rejilla 3D alrededor de la molécula (paso ~0.5 Å, margen ~5 Å). El cálculo en sí es una función pura `computePotentialGrid(atoms, charges, gridSpec)` en un módulo aparte, importada por el worker y por las pruebas.
  - Se pinta como superficie molecular (SES) coloreada con la rejilla: `VolumeData` de 3Dmol + `volscheme` rojo-blanco-azul. **Escala fija** (la misma para los 20), para que se puedan comparar entre sí; documentar el valor elegido.
  - Etiqueta visible junto a la nube: "Aproximación educativa (Coulomb a pH 7), no es un cálculo Poisson-Boltzmann (APBS)".
- **Superficie por hidrofobicidad** (aminoácido suelto): por átomo, no por residuo, porque en un aminoácido aislado el valor de Kyte-Doolittle sería un color uniforme. C, S y los H unidos a C → apolar (naranja); N, O y los H unidos a N/O → polar (azul verdoso). El valor de Kyte-Doolittle del aminoácido se muestra en la leyenda. Así Leu sale casi toda naranja y Ser muestra su parche polar del OH. En la Fase 4, para proteínas, se añadirá la versión por residuo.
- **Hidrógenos**: visibles por defecto (dejan ver que –NH2 y –COOH están neutros), con interruptor "Mostrar hidrógenos" para despejar la vista.
- **Etiquetas**: nombres de átomo del CCD (CA, CB, OG…) en los átomos pesados, tomados de `atom-names.json`.
- **Medir**: modo medición en la barra; clic en 2 átomos → distancia (Å), 3 → ángulo (°), 4 → diedro (°). Línea discontinua + etiqueta en 3D; botón "borrar medidas". La geometría (distancia, ángulo, diedro) va en `src/chem/geometry.ts`, pura y probada; la Fase 5 la reutilizará para φ/ψ/χ.
- **Centrar/restablecer** y **captura PNG** (`pngURI()` → descarga `aminolab-{código}.png`).
- **"¿Qué estoy viendo?"**: cada representación, modo de color, superficie y herramienta lleva un ícono ⓘ con 1–2 frases originales. Los textos viven en `src/components/MolViewer/explanations.ts` (son textos de interfaz, no datos bioquímicos).
- **Anti-spoiler**: con `spoilerFree`, los modos `group`, `hydrophobic`, `kyte-doolittle`, `polarity`, `charge`, ambas superficies y las etiquetas quedan desactivados en la barra (y forzados a `element` / `none` / sin etiquetas si llegaban por props); el visor no muestra nombre ni código. Se implementa ya aunque ninguna pestaña lo use hasta la Fase 3.
- Responsive: el lienzo ocupa el ancho disponible con relación de aspecto fija; en celular la barra se pliega en un menú. Al desmontar, liberar el visor de 3Dmol y terminar el worker (en "comparar" habrá dos visores a la vez).

### Desviaciones y notas
- **Nube**: `VolumeData` de 3Dmol funciona como describe el handoff; se construye vacío y se le asigna la rejilla calculada (no se usó la alternativa por átomo).
